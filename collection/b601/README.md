# B601-DM 棋子抓放数据采集

这套工具用一台 Mac、一台 reBot B601-DM、USB-CAN 转接器和一台相机录制示教。操作员用键盘移动末端和开合夹爪，每次完整的抓、搬、放保存为一条 LeRobot episode。另一台电脑只分析采集流程或读取文件时，无需连接机械臂。

| 文件 | 作用 |
| --- | --- |
| [b601_pick_place.py](b601_pick_place.py) | 相机读取、只读关节探测、运动学与控制循环、终端示教和数据写入 |
| [b601_teach_app.py](b601_teach_app.py) | macOS 界面、相机选择、键盘和鼠标输入、开始录制和保存 |
| [workspace-bounds.example.json](workspace-bounds.example.json) | 原采集台的 XYZ 工作区示例，单位为米 |
| [models/ReBot_Arm_DM.urdf](models/ReBot_Arm_DM.urdf) | 采集器读取关节原点、转轴、限位和末端变换的模型 |

## 在采集电脑上运行

用 Python 3.11 创建独立的采集环境。在仓库根目录执行：

```bash
python3.11 -m venv .venv-lerobot
source .venv-lerobot/bin/activate
python -m pip install -r collection/b601/requirements.txt
```

先用当前机器的串口和相机编号替换下面的示例。相机编号以本次预览为准，macOS 可能会请求摄像头权限。姿态命令读取六个关节和夹爪的反馈，并输出模型计算的末端位置。

```bash
ls /dev/cu.usbmodem*
port=/dev/cu.usbmodem00000000050C1
camera=1
python collection/b601/b601_pick_place.py camera --camera "$camera" --output /tmp/b601-preview.jpg
open /tmp/b601-preview.jpg
python collection/b601/b601_pick_place.py pose --port "$port"
```

将工作区示例复制为 `workspace-bounds.local.json` 并根据现场测量调整，顺序为 `[XMIN, XMAX, YMIN, YMAX, ZMIN, ZMAX]`，相对于机械臂底座。边界约束模型的末端参考点 `end_link`。测量时要给夹指、桌面和其他物体留出空间，并核对关节零位和夹爪方向。参见 [Seeed 的 B601-DM 上手与零位流程](https://wiki.seeedstudio.com/rebot_b601_dm_getting_started/)。

```bash
cp collection/b601/workspace-bounds.example.json collection/b601/workspace-bounds.local.json
# 编辑 workspace-bounds.local.json，填入当前工位测得的工作区。
open -n "collection/b601/B601 Teach.app" --args \
  --port "$port" --camera "$camera" \
  --bounds "$PWD/collection/b601/workspace-bounds.local.json"
```

也可以用终端采集单条示教。把六个大写占位符替换成测量值，并为每条示教指定一个新目录：

```bash
python collection/b601/b601_pick_place.py record \
  --port "$port" --camera "$camera" \
  --bounds XMIN XMAX YMIN YMAX ZMIN ZMAX \
  --output data/b601/pick-place-pilot-01
```

## 操作和保存

1. 预览画面，确认能看到棋子、蓝色目标格和夹爪。图形界面点「检查连接」读取姿态并验证工作区，通过后点「使能电机」。终端版通过检查后会要求输入 `ENABLE`。
2. 摆好棋子和机械臂起始位置，按 `R` 开始录制。用 `W/S` 沿 X 正向或负向移动，`A/D` 沿 Y 正向或负向移动，`E/C` 升降，`O/P` 打开或闭合夹爪。腕部保持会话启动时的朝向。
3. `F` 切换细调和快档。水平细调每次 2 mm，快档优先尝试 6 mm；升降分别从 4 mm 或 6 mm 起步，受限时尝试更小步长。图形界面的水平快档按住移动，松开、拖出按钮或窗口失焦时取消前方目标并保持当前位置。
4. 棋子放下后松夹，确认棋子直立、底座中心留在蓝色目标格内。按 Enter 保存，等到界面显示已保存的帧数。图形界面可直接录下一条，并通过「打开数据目录」定位文件。
5. 把机械臂停在有稳固支撑的位置后结束示教。终端版用 `Q` 或 Esc。退出会解除电机扭矩，程序不会自动回零。

## 数据怎样写入

录制循环以 10 Hz 为目标。每次循环读取相机和实测状态，处理操作员输入，更新并记录实际下发的位置目标。如果这一帧没有发送新命令，`action` 继续记录上一次已应用的目标；录制会话启动时用实测位置初始化目标。相机时间是 Mac 收到图像的时间；分析实际采样间隔时用 `timing.csv`，LeRobot 的 `timestamp` 按帧号和标称帧率生成。

| 字段或文件 | 内容 |
| --- | --- |
| `observation.images.front` | 单路 RGB 图像，采集请求 640×480，实际形状见 `meta/info.json`；图像字节保存在 Parquet 中 |
| `observation.state` | 七维 float32，六个关节和夹爪的实测电机角度 |
| `action` | 七维 float32，实际应用的位置目标，与实测状态使用同一套电机角度单位和顺序 |
| `timing.csv` | 帧号、图像收到时间、反馈读取完成时间、命令发送完成时间（单调时钟，纳秒）、输入键，以及六个关节的速度和扭矩反馈 |
| `meta/` | 数据格式、字段顺序、统计量、任务和 episode 元数据 |

每条示教单独保存在 `data/b601/pick-place-…/`。转移原始数据时保留完整目录。读取时核对 `meta/info.json`、Parquet 和 `timing.csv` 的帧数，再检查最终松夹画面。整理训练集时按整条示教划分，并排除空目录和仅用于保存起始姿态的静止采样。原始录制和本机工作区配置由仓库根目录的 `.gitignore` 排除。

## Windows 末端手动控制窗口

本机的 `scripts/b601_manual_control.py` 提供 Windows 原生操作窗口，使用 `real_robot/manual_control.py` 的运动学与路径检查。窗口已经从只保持进程接管 COM5，接管时保留电机使能状态；默认暂停，点击“开始键盘控制 / 继续”后操作。

| 按键 | 动作 |
| --- | --- |
| W / S | 底座 X 正向 / 负向，每次目标平移 6 mm |
| A / D | 底座 Y 正向 / 负向，每次目标平移 6 mm |
| ↑ / ↓ | Z 升高 / 降低，每次目标平移 6 mm |
| ← / → | 夹爪张开 / 闭合，每次 8 电机度，受夹爪限位约束 |
| Esc | 暂停并保持当前位置 |

长按不连发，上一动作尚未到位时不排队。平移保持按键起始时的末端朝向；越界或逆运动学无解时整步拒绝，不自动缩短到其他步长。机械臂默认采用联调慢速 5 电机度/秒，夹爪为 12 电机度/秒；本次用户要求加速后，已在会话配置 `joint_velocity_deg_s` 中恢复原采集使用的机械臂 30 电机度/秒、夹爪 12 电机度/秒。没有将速度设置为无上限，也没有改写电机硬件寄存器。机械臂目标插值下发并检查关节与工作区路径；夹爪发送单次有界目标，用行程和进展检查识别卡滞，不套用机械臂的 2° 跟踪误差阈值。失去窗口焦点会暂停，关闭窗口会最小化并继续保持使能，不自动回零或解除扭矩。

启动参数为 `--setup`（已核对的运动学/端口/限位配置）、`--output`（本地会话目录）及可选 `--sdk-dir`。本次会话在 `data/b601/manual-teleop-20261114/`，保存 `setup.json`、`teleop-status.json` 和每次接受按键的 `manual-events.jsonl`。实际位移仍受模型、零位和反馈误差影响；界面同时显示实测和目标 XYZ。

加入 `--model-control` 时，由同一控制进程接收有时效的单步请求，同时读取 RealSense 相机；不另开串口控制器。WSL 入口 `scripts/run_b601_model_trial.py --session SESSION --steps 10 --duration 30` 加载已评估的 EMA＋DDIM 10 候选。先按实测反馈逐步对齐已保存的机械臂参考姿态，保持夹爪开度，再使用最新两帧观测闭环执行。每步保留预测方向，最多改变 0.5 臂关节电机度、2 夹爪电机度和 6 mm 末端距离，完成后自动暂停。原始预测、有界目标和实测到位值保存于 `model-trial-events.jsonl`；这些限幅小步不代表完整速度下的任务复现或抓放成功。

新版窗口左侧直接显示 640×480 实时 RGB，并提供“运行模型”和“暂停并保持”按钮；右侧保留键盘操作。预览与推理复用同一个 RealSense 管线，不启动第二个相机或串口控制器。“运行模型”在 WSL 启动 `--continuous --duration 300 --resume`，持续使用新观测推理并执行，最长 5 分钟，不受短试跑 10 步数量限制。相机断流、边界或跟踪异常会停止；Esc、窗口失焦或手动接管会使本次运行失效，下一次推理不能自动恢复动作。停止后需显式点击按钮开始新一轮。

初版实时会话为本地 `data/b601/live-model-20261114-01/`，在 61 步后由操作员暂停。该版本只保存采样图像、关节输入和单步执行事件，没有连续视频等完整记录，已有缺失不能补录。

用户随后要求补齐记录，当前会话为 `data/b601/live-model-recorded-20261114-01/`，进程指针仍为 `data/b601/active-controller.json`。点击“运行模型”会先开启记录，再加载并运行模型；暂停或运行结束后自动写完本段。每段使用新的 `recordings/UTC-随机标识/` 目录，文件如下：

| 文件 | 内容 |
| --- | --- |
| `rgb-*.mkv` | 30 fps、640×480、H.264 RGB 无损连续视频，约每 5 秒一段 |
| `depth/*.npz` | 原始 uint16 Z16 深度，15 帧一块无损压缩；最后不足 15 帧也保存 |
| `frames.jsonl` | 视频帧序号、RGB/深度传感器帧号、接收及传感器时间戳、时钟域，可据此识别源帧缺口 |
| `control-cycles.jsonl` | 每个控制周期的七电机位置、速度、扭矩、温度、状态、CAN 标识、下发目标、末端位置和时序 |
| `manifest.json` | 起始时间、相机内参、深度单位和深度到彩色外参、写入计数、完成或失败状态 |
| 会话根目录 `predictions.jsonl` | 每次推理完整 16×7 预测和可执行 8×7 片段、输入标识、随机种子、时间戳、检查点和记录标识；在执行前落盘，拒绝执行也保留预测 |

每次采样的 `UUID.npz` 仍保存两帧全分辨率 RGB 和两组关节输入；原有执行事件、故障和运行日志继续保留。记录线程与控制线程分开，排队溢出、编码或写盘异常会停止模型，未开启记录时不能继续模型操作。SDK 缓存没有单电机接收时间戳，该限制保留在清单中。关闭或重启控制进程前，需先暂停模型并等待记录 `finalized=true`，避免截断最后一段视频或深度块。

静态真机验证读回了 188 帧视频、188 帧深度和 124 个控制周期，无相机源帧缺口；第二段验证读回 45 帧视频、45 帧深度、30 个周期和一次真实模型的完整预测，模型输入两帧与解码视频逐像素一致。验证期间没有模型运动指令，窗口继续保持暂停，下一次明确启动模型时自动同步记录。

用户随后要求采用原方法的动作序列与滚动时域执行。`--rhc` 对照原仓库 `eval_real_robot.py`：推理时将可执行未来长度设为 `horizon - n_obs_steps + 1 = 15`，以最后观测的 Windows 接收时间加 100 ms 间隔构造动作时间戳，每 6 步（0.6 秒）重新观察和推理，覆盖尚未执行的未来目标，并丢弃已过期目标。控制端独立调度，不逐动作等待到位，也不将预测缩放为 0.5° 小步。保留工作区、关节、跟踪、采集时的 2°/8° 单步范围、记录和时效保护；整段过期或调度严重迟到会暂停。已验证的 EMA＋DDIM 10 候选不变，属于 B601 硬件适配的滚动时域执行。

第一轮完整任务预实验目录为 `data/b601/experiments/rhc-trial-001/`，协议与参考起点在 `protocol.json` 和 `setup.json`。该轮先恢复全部七维参考姿态，再启动模型序列。`predictions.jsonl` 除完整 16 步与前 8 步外，增加实际调度的 15 步及时间戳；`sequence-actions.jsonl` 保存真正下发的目标、原序列索引、计划和实际发送时间。下发时沿用采集驱动的逐关节相对目标裁剪（臂关节 2°、夹爪 8°），记录原始和真正接受目标，不做全局比例缩放。

该轮的工程预检先后修正了绝对夹爪目标的校验语义、新旧序列接收时间微小抖动产生重复目标，以及旧运行状态误关新录制的问题；全部尝试均保留在 `attempts/`、预检记录与独立录制目录中。最后一次实际运行 **14.10 秒，23 次滚动推理，下发 129 个动作**；动作间隔中位数 **100.11 ms**、P95 **130.36 ms**，随后因调度迟到超过 75 ms 触发保护，未完成抓放。`outcome.json` 将结果标为时序保护中断，不能据此评定策略的抓放成功率。终止时臂关节最大跟踪误差约 0.42°，七电机使能且暂停保持。下一步先把采样序列化、IPC 和文件操作移出执行调度线程，进行完整记录负载下的时序验证，再启动下一轮任务实验。

后续已完成时序隔离修复：`real_robot/io_workers.py` 的后台工作线程处理请求文件、两帧 NPZ 打包、序列预检、回复和事件日志；控制线程只消费内存队列，并再次核对控制代号、输入年龄和当前状态。取消操作会使已经预处理的旧目标失效。反馈/保护循环从 20 Hz 提高到 50 Hz，模型目标仍为标称 10 Hz，原 75 ms 调度保护及其他限值不变；事件日志队列溢出或后台错误会暂停模型。控制记录新增反馈、决策和下发各阶段耗时。

`rhc-timing-validation-001` 在真实 GPU 推理、RGB/深度录制和固定目标下完成 60 秒验证：100 次推理、572 个本轮保持目标，最大下发迟到 30.81 ms，无故障。此前一段 45 秒测试由窗口切换触发暂停，记录另存。`rhc-trial-002` 随后实际运行 171.73 秒、286 次推理、1,638 个动作；下发间隔中位数 101.59 ms、P95 104.62 ms，最大迟到 44.97 ms，未复现调度故障。

抓放复测结果为**接近失败，未接触棋子**，依据操作员现场反馈记录，不计成功。最终因腕俯仰反馈 57.429° 超过训练统计上界 57.320° 加 0.05° 容差而停止；这是训练状态范围检查，物理关节及工作区检查均通过。5,935 帧视频、5,935 帧深度、9,656 个控制周期及 286 条完整预测已回读核对，无相机源帧缺口。85 项测试通过。完整结果在本地 `data/b601/experiments/rhc-trial-002/outcome.json`；下一步检查现场与实际训练示范的起始构图、七维姿态及接近轨迹，不能把时序修复计作抓放复现成功。

操作员请求第二次任务实验时，新目录为 `rhc-trial-003`（`operator_trial_number=2`）。本轮自动对齐旧静态参考姿态执行了 39 次准备动作，视频与反馈运动学对齐显示 X 约由 332.4 mm 退到 285.3 mm；完整录制约 63.9 秒中未下发任何模型序列动作。随后首段模型请求因观测过期被拒绝。因此这轮标为 `aborted_before_policy_execution`，不能计为模型抓放试验。操作员指出棋子位于 +X、末端却向底座退，回看确认负 X 段由自动参考对齐造成。该参考的来源本来就是非训练示范的静态记录，启动前未核对与现场棋子位置的关系。

视频抽帧、XYZ（来自关节反馈与 URDF）对齐、原始/执行预测方向核对存于 `data/b601/experiments/direction-review/`。上一轮 `rhc-trial-002` 模型阶段整体沿 +X，从约 285.4 mm 到 349.1 mm，但在 X≈327 mm 附近停留，末期 Z 从约 27.5 mm 升至 49.7 mm且未接触棋子。不能用本轮复位解释上一轮策略的接近失败，也没有证据支持整体翻转 X 或电机符号。应先将参考对齐与模型运行的启动流程分开，基于真实示范首帧核对现场与起点，再以只预测方式复核接近方向。当前停止模型并保持电机使能，未发额外方向测试动作。

用户指定当前位置起跑后，`rhc-trial-004/start-pose.json` 保存了当时的七维反馈与末端位置，关闭自动参考对齐。`--resume` 只检查当前观测；执行端在 `align_reference_on_start=false` 时拒绝参考对齐请求，避免启动后再次退回旧静态姿态。本轮实际运行 54.67 秒、91 次推理、517 个动作，未发送参考对齐动作。观察到末端向 −X、+Y 偏移后助手主动暂停；全部臂关节下发目标与原始策略目标一致，偏移发生在策略执行阶段。结果标为 `assistant_stopped_wrong_approach_direction`，抓放仍未成功。记录和离线核对在该目录，继续上机前需检查冻结输入与训练示范的接近动作。
